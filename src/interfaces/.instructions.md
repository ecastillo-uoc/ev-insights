# Interfaces Module — Instructions

## Purpose

Data access abstraction layer. Each interface provides a uniform API for reading data, saving models, persisting predictions, and managing the database, regardless of the backend (file system, PostgreSQL, MLflow, external API).

## File Inventory

| File | Class | Backend |
|------|-------|---------|
| `interface.py` | `Interface` (abstract) | Base class + `init_interface()` factory |
| `file_interface.py` | `File` | CSV/XLSX/JSON files on disk |
| `postgresql_interface.py` | `PostgreSql` | PostgreSQL via `psycopg2` |
| `mlflow_interface.py` | `MLflow` | MLflow tracking server + MinIO |
| `api_acn.py` | `AcnApi` | External ACN data API |

## Class Hierarchy

```
Interface (abstract)
├── File
├── PostgreSql
├── MLflow
└── AcnApi
```

## Factory: `init_interface(config) → Interface`

Dispatches on `config["name"]`:
- `"File"` → `File(name, type, input_dir, output_dir, limit_rows, input_data_type, datasets_list, datasets_details_file)`
- `"PostgreSql"` → `PostgreSql(name, type, output_dir, host, port, user, password, database)`
- `"MLflow"` → `MLflow(name, type, output_dir, mlflow_dir, host, port, user, password, bucket_name, init_storage)`
- `"Api"` → `AcnApi(...)`

Valid names tracked in `INTERFACES = {"File", "MySql", "PostgreSql", "MLflow"}`.

## Abstract Interface Contract

```python
get_data(data_selection: dict) → pd.DataFrame
save_forecast_model(forecaster_name, results, file_path, algo)
get_model(algo, model_name, models_dir)
save_forecast_prediction(forecaster_name, actor, model, experiment_id, run_id, results, algo)
init_db()
delete_dataset(dataset_name)
close_interface()
```

## PostgreSQL Interface Details

- **Driver**: `psycopg2` with `RealDictCursor`.
- **Queries**: All SQL lives in `src/sql/postgresql/sql_query.py` as string constants.
- **UI-facing helpers**: `get_datasets_names()`, `get_countries()`, `get_years()`, `get_charging_point_types()`, `get_filtered_record_count()` — used by the Streamlit UI for hierarchical filtering.
- **Data retrieval**: `get_data(data_selection)` builds dynamic queries from field filters.
- **Connection lifecycle**: Opened in `__init__`, closed in `close_interface()`.

## File Interface Details

- Supports `bulk` and `table` ingestion modes via `input_data_type`.
- Auto-detects dataset content type (EV data, infrastructure, sessions).
- Reads CSV, XLSX, JSON based on `datasets_details.csv` metadata.
- Applies column mapping and schema validation.

## MLflow Interface Details

- Stores trained models and experiment metadata.
- `get_model()` retrieves a model by name and algorithm.
- Integrates with MinIO for artifact storage.

## Refactoring Considerations

- **Missing ABC inheritance**: `Interface` uses `@abstractmethod` without inheriting `ABC`.
- **`MySql` is listed in `INTERFACES` but may not be implemented/maintained**: Verify and either implement or remove.
- **Fat PostgreSQL interface**: `postgresql_interface.py` likely contains both data-access and UI-query logic. Consider splitting into a data-access class and a read-only query service.
- **Credential handling**: DB credentials are passed as plain config values. Consider environment variables or a secrets manager for production.
- **SQL injection surface**: Verify that `sql_query.py` uses parameterized queries, not string formatting, for user-supplied values.
- **`PureWindowsPath` in `Interface.__init__`**: Cross-platform path conversion is unnecessary on Linux-only deployments.
- **Connection pooling**: `psycopg2` connections are single-use per interface instance — consider connection pooling for the API/UI use case.
