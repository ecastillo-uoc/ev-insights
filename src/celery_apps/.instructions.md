# Celery Apps Module — Instructions

## Purpose

Asynchronous task execution layer using Celery with Redis as broker and backend. Allows the API to dispatch long-running operations (training, ingestion, analysis) without blocking HTTP responses.

## File Inventory

| File | Role |
|------|------|
| `worker.py` | Celery app configuration (broker, backend, task discovery) |
| `tasks/__init__.py` | Empty |
| `tasks/admin_tasks.py` | Empty — placeholder for admin async tasks |
| `tasks/analysis_tasks.py` | `@celery_app.task` wrappers for analysis operations |
| `tasks/forecast_tasks.py` | `@celery_app.task` wrappers for forecast operations |
| `tasks/ingestion_tasks.py` | `@celery_app.task` wrappers for ingestion operations |

## Celery Configuration (`worker.py`)

```python
celery_app = Celery(
    broker='redis://127.0.0.1:6379/0',
    backend='redis://127.0.0.1:6379/0',
    include=[admin_tasks, analysis_tasks, forecast_tasks, ingestion_tasks]
)
```

- **Broker/Backend**: Redis (localhost:6379).
- **Visibility Timeout**: 12 hours (configurable via environment).
- **Task Auto-discovery**: Via `include` list in Celery constructor.

## Conventions

- Tasks are decorated with `@celery_app.task`.
- Tasks call `init_service()` or domain logic directly, passing JSON config.
- Redis is expected to be running for Celery to function.

## Refactoring Considerations

- **`admin_tasks.py` is empty**: Implement or remove.
- **Hardcoded Redis URL**: Move broker/backend URLs to environment variables or config file.
- **No retry/error handling**: Tasks should define `max_retries`, `retry_backoff`, and handle transient failures.
- **No result serialization control**: Celery defaults may not handle DataFrames or complex results — verify serializers.
- **Task granularity**: Current tasks may wrap entire service runs. Consider finer-grained tasks for progress tracking.
