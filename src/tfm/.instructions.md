# TFM Module — Instructions

## Purpose

Master's thesis (TFM) experiment runner.  This module is the **top-level entry
point** for batch forecasting experiments and EDA figure generation.  It sits
above the core `forecast/` engine and delegates all computational work to
canonical modules (`src.forecast.pipeline`, `src.data.data_fetcher`,
`src.forecast.optimization`).

## File Inventory

| File | Role |
|------|------|
| `tfm_forecast.py` | Experiment orchestrator — wires dataset configs and strategy params, then calls `run_forecast_pipeline()` |
| `tfm_plots.py` | EDA figure runner — iterates datasets and calls `src.analysis.dataset_plots` functions |

## Key Functions

### `tfm_forecast.py`

| Function | Description |
|----------|-------------|
| `get_dataset_config(dataset_name, hussain=False)` | Returns `(split_date_str, ranges_dict)` with train/test/zoom date ranges per dataset |
| `execute_lstm(datasets, li_forecast_horizons, …)` | Run LSTM forecasts for each dataset × horizon |
| `execute_transformer(…)` | Run Transformer forecasts |
| `execute_lightgbm(…)` | Run LightGBM forecasts |
| `execute_xgboost(…)` | Run XGBoost forecasts |
| `execute_hybrid(…)` | Run Hybrid LSTM-Transformer forecasts |
| `execute_hussain_lstm(…)` | LSTM with Hussain et al. (2025) hyperparams |
| `execute_hussain_transformer(…)` | Simplified Transformer from Hussain et al. |
| `execute_hussain_hybrid(…)` | Hybrid with Hussain et al. hyperparams |
| `optimize_lstm(datasets, n_trials, …)` | Optuna hyper-parameter search for LSTM |

### `tfm_plots.py`

| Function | Description |
|----------|-------------|
| `main()` | Generates EDA figures (trends, decomposition, boxplots) for configured datasets |

## Hussain et al. (2025) Reproduction

Three `execute_hussain_*` functions reproduce the architectures and
hyperparameters described in Hussain, A. et al. "Charging stations demand
forecasting using LSTM based hybrid transformer model" *Sci Rep* 15, 13555
(2025).

Key differences from our default models:
- `look_back = forecast_horizon` (not a fixed 14)
- `dropout = 0.2` (vs 0.1 default)
- `ReduceLROnPlateau` + `EarlyStopping` callbacks
- COVID data **included** (`exclude_covid=False`) to match article methodology
- Prediction uses schedule (multi-step recursive) mode

## Conventions

- Logging via `logging.basicConfig()` (standalone, not the framework `Logger`).
- ANSI color highlighting via `Colors` from `src.utils.console`.
- Output plots go to `output_plots/` at project root.
- `tfm_plots.py` uses `matplotlib` (not Plotly).
- `__main__` block configures datasets, horizons, and `split_date_str`, then
  calls the `execute_*` functions sequentially.

## Known Issues

- **`optimize_lstm()` free variables**: Uses `split_date_str` and
  `li_forecast_horizons` which are only defined in the `if __name__ ==
  "__main__"` block — calling this function from outside `__main__` will raise
  `NameError`.  Fix: pass them as parameters.
- **Hardcoded paths in `tfm_plots.py`**: Figure output path and DB credentials
  are hardcoded.  Consider using config or environment variables.
