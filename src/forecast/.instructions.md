# Forecast Module — Instructions

## Purpose

Core forecasting engine implementing the **Strategy pattern** for pluggable data-preparation and ML-model logic. Supports training and prediction for session-level and station-level targets using LightGBM, XGBoost, LSTM, Transformer, and Hybrid models.

## File Inventory

| File | Role |
|------|------|
| `forecast.py` | `Forecast` abstract base class + `init_forecast()` factory |
| `generic_forecast.py` | `GenericForecast` — composes a `PredictionTargetStrategy` + `ModelStrategy` |
| `forecast_definitions.py` | Pre-wired `GenericForecast` subclasses (one per algo×target combo) |
| `forecast_implementations.py` | Concrete strategy implementations (data + model) |
| `model_registry.py` | `ModelStrategyType` enum + `MODEL_STRATEGY_REGISTRY` |
| `prediction_target_registry.py` | `PredictionTarget` enum + `PREDICTION_TARGET_REGISTRY` |
| `model_persistence.py` | Save/load model files (`.ubj`, `.keras`, `.pkl`) |
| `helpers.py` | Grid search & hyperparameter utilities |
| `split_dataset.py` | Train/test splitting logic |
| `lstm.py` | LSTM-specific model code |
| `lightgbm_forecast.py` | LightGBM-specific forecast (legacy, pre-strategy) |
| `gnb.py` | Appears unused — candidate for removal |
| `strategies/interfaces.py` | ABC definitions: `PredictionTargetStrategy`, `ModelStrategy` |
| `strategies/utils_ts.py` | Time-series feature engineering helpers (lags, SMAPE, etc.) |

## Strategy Interfaces

### PredictionTargetStrategy (data side)

```python
feature_engineering(df, custom_params) → (df, feature_columns, target_columns)
check_data(df) → df
```

**Implementations**: `SessionDataStrategy`, `StationChargesDataStrategy`, `StationEnergyDataStrategy`

### ModelStrategy (ML side)

```python
train(df, feature_columns, target_column, dataset_names, model_name_prefix) → dict
predict(df, feature_columns, target_column, model_objects, context_date, dataset_names, submode) → dict
```

**Implementations**: `LightGBMModelStrategy`, `XGBoostModelStrategy`, `LSTMModelStrategy`, `TransformerModelStrategy`, `HybridTransformerLSTMModelStrategy`

## Registry System

### Model Registry (`model_registry.py`)

- `ModelStrategyType` enum: `LIGHTGBM`, `XGBOOST`, `LSTM`
- `MODEL_STRATEGY_REGISTRY`: maps enum → `ModelStrategyInfo(name, display_name, description, strategy_class, default_params)`
- Factory: `get_model_strategy(strategy_type) → ModelStrategy`

### Prediction Target Registry (`prediction_target_registry.py`)

- `PredictionTarget` enum: `SESSION_ENERGY`, `SESSION_DURATION`, `STATION_CHARGES`, `STATION_ENERGY`
- `PREDICTION_TARGET_REGISTRY`: maps enum → `PredictionTargetInfo(name, display_name, description, strategy_class, default_params, init_params)`
- Factory: `get_prediction_target_strategy(target_type) → PredictionTargetStrategy`
- Includes default field lists and custom_params per target type.

## Forecast Factory (`init_forecast`)

1. Reads `config["name"]` (e.g., `"lightgbm_station_energy"`).
2. If `prediction_target` and `model_strategy` keys exist in config, uses registries to build strategies dynamically.
3. Otherwise, falls back to importing a pre-defined class from `forecast_definitions.py` by name.
4. Injects strategies into `GenericForecast.__init__()`.

## Execution Flow

```
ForecastService.run()
  → init_forecast(config)          # factory
  → forecast.load_data(df)         # from interface
  → forecast.check_data()          # via data_strategy
  → forecast.feature_engineering() # via data_strategy
  → forecast.run()                 # delegates to train() or predict()
      → model_strategy.train()  OR  model_strategy.predict()
```

## Model Persistence

- `save_model(name, results, models_dir, algo)` — dispatches on algo to save `.ubj` (boosting) or `.keras` + `.pkl` (neural).
- `load_model(algo, model_name, models_dir)` — auto-detects format.
- `list_models(models_dir)` — scans directory for available models.

## Refactoring Considerations

- **`forecast_implementations.py` is oversized** (~500+ lines): Contains ALL data strategies AND model strategies in a single file. Split into `data_strategies/` and `model_strategies/` sub-packages.
- **Registry incomplete**: `TransformerModelStrategy` and `HybridTransformerLSTMModelStrategy` exist in implementations but are NOT registered in `MODEL_STRATEGY_REGISTRY`. Register them or add a `TRANSFORMER` and `HYBRID` enum.
- **Copy-paste in registry metadata**: LSTM entry in `MODEL_STRATEGY_REGISTRY` has XGBoost's description and default_params.
- **`_resolve_model_strategy()` is a code smell**: Auto-switching strategies at predict time via type-checking (`isinstance`) indicates model ↔ strategy coupling. Better to persist the strategy type alongside the model.
- **`gnb.py` and `lightgbm_forecast.py`**: Legacy files that predate the strategy pattern. Confirm they are unused and remove.
- **`forecast_definitions.py` classes are boilerplate**: Each is only 4 lines. Consider generating them dynamically from the registry or removing them in favor of config-only instantiation through `init_forecast()`.
- **Circular import risk**: `model_registry.py` imports from `forecast_implementations.py`, and `generic_forecast.py` does lazy imports from the same file in `_resolve_model_strategy()`.
- **`custom_params` merging**: The factory merges registry defaults with config overrides; this logic is scattered and not well documented.
- **Missing Transformer/Hybrid in `PredictionTarget` combinations**: These model strategies work with station data but no pre-defined definitions exist.
