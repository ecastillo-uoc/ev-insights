# UI Module — Instructions

## Purpose

Streamlit-based web interface for EV-Insights. Provides pages for data ingestion, forecasting (train/predict), analysis visualization, and database management.

## File Inventory

| File | Role |
|------|------|
| `app.py` | Main Streamlit entry point — page config + sidebar navigation |
| `ingestion_app.py` | Data upload and ingestion workflow page |
| `forecast_app.py` | Model training and prediction interface |
| `analysis_app.py` | Statistical analysis and visualization dashboard |
| `db_manager_app.py` | Database administration (schema init, dataset deletion) |
| `shared_components.py` | Reusable components: `fetch_db_data()`, `render_data_selection()` |

## Application Structure

- **Entry**: `streamlit run src/ui/app.py` from the project root.
- **Navigation**: Sidebar radio selector with four pages.
- **Pages**: Each page is a `render_<name>_page()` function imported into `app.py`.

## Shared Components

### `fetch_db_data(config_file, datasets, countries, years, types)`

- Cached with `@st.cache_data`.
- Opens a temporary `PostgreSql` connection to fetch filter options.
- Returns dict with `datasets`, `countries`, `years`, `types`, `count`.

### `render_data_selection(config_file)`

- Renders hierarchical multi-select filters (Dataset → Country → Year → Type).
- Displays record count based on current selection.

## Import Handling

`app.py` has a dual-import fallback:
1. First tries `from src.ui.<module>` (when run from project root).
2. Falls back to relative imports (when run from `src/ui/` directly).

## Conventions

- Each page function is self-contained and renders its own Streamlit components.
- Database connections are opened and closed within `fetch_db_data()` — not persisted across requests.
- Config file path is passed to components that need DB access.

## Refactoring Considerations

- **Temporary DB connections**: `fetch_db_data()` creates and destroys a `PostgreSql` instance per call. Consider using `st.session_state` to manage a persistent connection or connection pool.
- **Dual-import fallback**: The try/except import pattern in `app.py` is fragile. Standardize on one execution mode.
- **No error boundary per page**: If one page crashes, Streamlit shows a full traceback. Add try/except wrappers with user-friendly messages.
- **Config file discovery**: Pages need to know the config file path. Consider a settings page or environment variable.
- **UI hardcoded to PostgreSQL**: `shared_components.py` directly imports `PostgreSql` — should go through the interface factory for consistency.
- **Missing loading states**: Long DB queries or training runs should show progress indicators.
