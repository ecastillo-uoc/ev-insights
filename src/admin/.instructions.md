# Admin Module — Instructions

## Purpose

Administrative and maintenance tasks: database schema initialization, dataset deletion with referential integrity, and other housekeeping operations.

## File Inventory

| File | Class | Role |
|------|-------|------|
| `admin.py` | `Admin` (abstract) | Base class + `init_admin()` factory + auto-discovery |
| `init_db.py` | `init_db` | Initializes the database schema |
| `delete_dataset.py` | `delete_dataset` | Deletes a dataset and its dependent records |
| `_sample_admin.py` | `_sample_admin` | Template for new admin tasks |

## Class Hierarchy

```
Admin (abstract)
├── init_db
└── delete_dataset
```

## Auto-Discovery

```python
ADMIN = [p.stem for p in Path(__file__).parent.glob("*.py")
         if p.name not in ["admin.py", "_sample_admin.py", "__init__.py"]]
```

Same pattern as the Analysis module — adding a new `.py` file with a matching class name auto-registers it.

## Factory: `init_admin(config, output_interface)`

- Dynamically imports `src.admin.<name>` and instantiates the class.
- Class name must match module filename (snake_case).

## Conventions

- Admin tasks receive the output interface (typically PostgreSQL) to perform operations.
- Each task implements a `run()` method.
- Results are logged but may not produce persistent output files.

## Refactoring Considerations

- **Thin abstraction**: With only two tasks, the auto-discovery + factory pattern may be over-engineered. Acceptable if more tasks are planned.
- **`_sample_admin.py`**: Good template — keep updated as patterns evolve.
