# API Module — Instructions

## Purpose

RESTful API layer built with FastAPI. Exposes analysis, forecast, ingestion, and admin operations as HTTP endpoints. Supports environment-based configuration (dev/test/prod).

## File Inventory

```
api/
├── api.py                     # FastAPI app setup + router registration
└── v1/
    ├── __init__.py
    ├── endpoints/
    │   ├── analysis.py        # POST /stats/
    │   ├── forecast.py        # POST /train/, POST /predict/
    │   ├── ingestion.py       # Ingestion endpoints
    │   └── admin.py           # Admin endpoints
    └── models/
        ├── analysis.py        # Pydantic: Stats
        ├── forecast.py        # Pydantic: TrainModelsDataParams, PredictModelsDataParams
        └── ingestion.py       # Pydantic: ingestion models
```

## API Setup (`api.py`)

- Reads `SERVICE_ENVIRONMENT` env var to select config path (`dev`/`test`/`prod`).
- Loads service configuration from `conf/api/` JSON files.
- Registers v1 routers with FastAPI `include_router()`.
- Swagger docs at `/docs#/`.

## Endpoints (v1)

| Method | Path | Request Model | Purpose |
|--------|------|---------------|---------|
| POST | `/stats/` | `Stats(entity, id)` | Run stats analysis |
| POST | `/train/` | `TrainModelsDataParams` | Train forecast model |
| POST | `/predict/` | `PredictModelsDataParams` | Generate predictions |

## Integration Points

- **APScheduler**: Used for scheduled forecast execution.
- **Celery**: Endpoints can dispatch long-running tasks asynchronously via `celery_apps/tasks/`.
- **Services**: Endpoints call `init_service()` or domain logic directly.

## Conventions

- Request/response models are Pydantic `BaseModel` subclasses in `v1/models/`.
- Endpoints are organized by domain in `v1/endpoints/`.
- API versioning via URL prefix (`/v1/`, `/v2/`).

## Refactoring Considerations

- **Config loading in `api.py`**: Reads JSON files at import time — should be deferred to app startup.
- **No input validation beyond Pydantic**: Consider adding business-rule validation (e.g., valid dataset names, date ranges).
- **Error responses**: Verify that domain exceptions are caught and returned as proper HTTP error codes, not 500s.
- **Scheduler setup**: APScheduler config is tightly coupled to `api.py` — consider separating into its own module.
