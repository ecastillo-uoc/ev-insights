# EV-Insights — Global Code Instructions

## Project Overview

EV-Insights is a framework for ingesting, analyzing, and forecasting EV (electric vehicle) charging session data. It was originally developed as a base framework and has been extended in this TFM (Trabajo Final de Máster) with new deep-learning models (LSTM, Transformer, Hybrid), a Streamlit Web UI, and architecture/I-O improvements.

## Architecture & Design Patterns

### Layered Architecture

1. **Interface Layer** — UI (Streamlit), CLI (`__main__.py`), API (FastAPI)
2. **Service Layer** — `services/` orchestrates the lifecycle of each domain operation
3. **Domain Layer** — `analysis/`, `forecast/`, `admin/` contain business logic
4. **Data Access Layer** — `interfaces/` abstracts PostgreSQL, file, MLflow, external APIs

### Key Design Patterns

| Pattern | Where | Notes |
|---------|-------|-------|
| **Factory** | `init_service()`, `init_forecast()`, `init_analysis()`, `init_interface()`, `init_admin()` | All use config dicts to instantiate the correct subclass |
| **Strategy** | `forecast/strategies/` | `PredictionTargetStrategy` (data) + `ModelStrategy` (ML algo) are plugged into `GenericForecast`. Neural strategies share `base_keras._KerasModelStrategy` template method. |
| **Registry** | `model_registry.py`, `prediction_target_registry.py` | Enum-keyed dicts mapping types to strategy classes + metadata |
| **Auto-discovery** | `analysis/analysis.py`, `admin/admin.py` | Module names are collected via `Path.glob("*.py")` — adding a file auto-registers it |
| **Template Method** | `Service.run()`, `Analysis.run()`, `Forecast.run()` | Base classes define the skeleton; subclasses fill steps |

### Configuration-Driven Execution

Everything is driven by JSON config files in `conf/cli/` or `conf/api/`. The config selects the service, interfaces, and specific tasks (analyses, forecasts, admin commands) to run.

```
config.json → __main__.py → init_service(config) → ServiceSubclass.run()
                                ↓
                    init_interface(config)  →  PostgreSql / File / MLflow
```

## Coding Conventions

### Naming

- **Modules/files**: `snake_case.py` (e.g., `forecast_definitions.py`)
- **Classes**: Usually `snake_case` matching the module name for auto-discovery (e.g., class `stats` in `stats.py`, class `lightgbm_station_charges` in `forecast_definitions.py`). Base/framework classes use `PascalCase` (e.g., `GenericForecast`, `AnalysisService`).
- **Factory functions**: `init_<thing>(config, ...)` pattern returns an instance or `None`.
- **Enums**: `PascalCase` class, `UPPER_SNAKE` members (e.g., `ModelStrategyType.LIGHTGBM`).
- **Constants**: `UPPER_SNAKE_CASE` (e.g., `DEFAULT_DATAFRAME_COLUMNS`).

### Logging

- Use `logging.getLogger('<module_name>')` — one logger per logical area.
- Logger is configured in `src/utils/logger.py` (rotating file + console + optional email).
- `Colors` class in `src/utils/console.py` provides ANSI color codes for terminal output highlighting.
- `rich.Console` also available in `src/utils/console.py` for enhanced terminal formatting.
- Debug traces use `logger.debug(f"[ClassName.method] ...")` with `[ClassName.method]` prefix and `Colors.XXX` highlighting.

### Path Handling

- Cross-platform path normalization is centralized in `src/utils/path_utils.normalize_path()` which wraps `PureWindowsPath(...).as_posix()`.
- Output directories are created eagerly with `mkdir(parents=True, exist_ok=True)`.

### Data Flow

- Data is passed as `pandas.DataFrame` throughout the pipeline.
- `data_selection` dict controls what data is fetched from the interface.
- Feature engineering transforms columns in-place and returns `(df, feature_columns, target_columns)`.

### Error Handling

- Factories raise `Exception` with descriptive messages when config is invalid.
- Services catch exceptions and append to output list.
- Many `# TODO` comments mark planned improvements.

## Adding New Components

### New Forecast Model

1. Create `forecast/strategies/<name>_strategy.py` implementing `ModelStrategy` (or subclassing `_KerasModelStrategy` for neural models).
2. Re-export in `forecast/strategies/__init__.py` and add to `__all__`.
3. Register in `model_registry.py` (`ModelStrategyType` enum + `MODEL_STRATEGY_REGISTRY`).
4. Optionally create a definition class in `forecast_definitions.py`.
5. Add model persistence support in `model_persistence.py` if file format differs.
6. Add the model-type string to `_STRATEGY_REGISTRY` in `pipeline.py` for TFM usage.

### New Analysis

1. Create `src/analysis/<name>.py` with a class matching the filename.
2. The class must extend `Analysis` and implement `check_data()`, `custom_settings()`, `run()`.
3. Auto-discovery picks it up (no registration needed).

### New Interface

1. Add to `INTERFACES` set in `interface.py`.
2. Implement the abstract methods of `Interface`.
3. Add the instantiation branch in `init_interface()`.

### New Service

1. Add name to `SERVICES` set in `service.py`.
2. Create `src/services/<name>_service.py` extending `Service`.
3. Add the instantiation branch in `init_service()`.

## Database

- **Engine**: PostgreSQL
- **Driver**: `psycopg2` with `RealDictCursor`
- **Schema**: defined in `src/sql/postgresql/schema.sql`
- **Queries**: centralized string constants in `src/sql/postgresql/sql_query.py`
- **Tables**: Dataset, ChargingStation, ChargingSession, User, ElectricVehicle, ChargingStationForecast, UserForecast

## External Dependencies

- **ML**: scikit-learn, LightGBM, XGBoost, TensorFlow/Keras (LSTM, Transformer)
- **Data**: pandas, numpy
- **Visualization**: matplotlib, plotly
- **Web**: FastAPI, Uvicorn, Streamlit
- **Async**: Celery + Redis
- **Experiment tracking**: MLflow + MinIO
- **Database**: psycopg2, SQLAlchemy (used sparingly in TFM module)
- **Optimization**: Optuna (TFM module)

## Known Technical Debt / TODOs

- Celery `admin_tasks.py` is empty.
- `_resolve_model_strategy()` in `GenericForecast` uses `isinstance` checks to auto-switch strategies — fragile coupling.
- **Dual DAL**: `data/data_fetcher.py` (SQLAlchemy) and `interfaces/postgresql_interface.py` (psycopg2) coexist with different connection approaches.
- `forecast/helpers.py` and `forecast/split_dataset.py` are deprecated but kept for reference.
