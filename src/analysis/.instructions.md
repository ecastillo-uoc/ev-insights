# Analysis Module — Instructions

## Purpose

Provides a library of data analysis modules for EV charging datasets. Each analysis retrieves data from the database, validates it, applies optional enrichment, runs its logic, and produces JSON/visualization outputs.

## File Inventory

## Auto-Discovery Mechanism

```python
ANALYSIS = [p.stem for p in Path(__file__).parent.glob("*.py")
            if p.name not in ["analysis.py", "_sample_analysis.py", "__init__.py"]]
```

Adding a new `.py` file to this directory with a class matching the filename automatically registers it.

## Analysis Lifecycle (managed by `AnalysisService`)

```
init_analysis(config) → Analysis instance
  → load_data(df)
  → check_data()
  → custom_settings()    # enrichment / clipping
  → run()                # core logic
  → save_output_to_file()
  → get_results() → dict
```

## Factory: `init_analysis(config, input_interface, output_interface)`

- Uses `importlib.import_module()` to dynamically load `src.analysis.<name>`.
- Class name must match the module filename (snake_case).
- Returns `None` if `enabled=False`.

## Key Conventions

- **Class names are snake_case** to match module filenames for dynamic import.
- Each analysis stores results in `self.results` (dict).
- Visualization uses Plotly and/or Matplotlib.
- `save_images`, `show_images`, `save_results` flags control output behavior.
- `data_selection` dict controls what data the service fetches.
- `custom_params` dict passes analysis-specific parameters (clipping, entity filtering, etc.).

## Refactoring Considerations

- **No typing on return values**: `run()` returns `None` in some analyses and `dict` in others — inconsistent.
- **`_sample_analysis.py`**: Good template but should be documented or linked from the developer tutorial.
