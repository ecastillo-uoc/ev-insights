# Utils Module — Instructions

## Purpose

Shared utilities: centralized logging, global constants and DataFrame schema definitions, and date/time helpers.

## File Inventory

| File | Role |
|------|------|
| `logger.py` | `Logger` class — rotating file handlers, console output, optional email alerts |
| `globals.py` | Constants: `DEFAULT_DATAFRAME_COLUMNS`, connector types, DB config functions |
| `date_utils.py` | Date/time utility functions |

## Logger (`logger.py`)

- Rotating file handler: 100 MB max, 10 backups.
- Console + file output with configurable formatters.
- Error-level email notifications via SMTP (optional).
- `Colors` class provides ANSI color codes for terminal output.
- Framework-wide: all modules use `logging.getLogger('<area>')`.

## Globals (`globals.py`)

### DataFrame Column Schemas

```python
DEFAULT_DATAFRAME_COLUMNS        # Core charging session fields
DEFAULT_EV_DATAFRAME_COLUMNS     # EV specifications
DEFAULT_CHARGING_STATION_DATAFRAME_COLUMNS  # Station metadata
```

### Constants

```python
DEFAULT_CHARGING_POINT_TYPES     # private_domestic, private_workplace, public
DEFAULT_CONNECTOR_TYPES          # T3, T2, TE, CHAdeMO, Combo
CONNECTOR_TYPE_ALIASES           # Maps variant names → standard codes
```

### DB Configuration Functions

- Functions that read DB connection parameters from environment variables.
- Functions to fetch valid connector types and charging point types from the database.

## Conventions

- All modules import `logging.getLogger(name)` — do not create new `Logger` instances directly.
- Column lists in `globals.py` define the canonical schema — changes here affect ingestion and analysis.
- `CONNECTOR_TYPE_ALIASES` is used during data normalization.

## Refactoring Considerations

- **`globals.py` mixes concerns**: Column definitions (pure data) live alongside DB-querying functions (side effects). Split into `constants.py` (pure) and `db_config.py` (DB-related).
- **DB config via env vars**: Good practice but currently mixed with `psycopg2` direct usage in globals — should go through the interface.
- **`Colors` class**: Simple ANSI codes — consider using `colorama` or `rich` for cross-platform support.
- **`date_utils.py`**: Verify it's used and not duplicated by pandas date operations in the forecast module.
